# 머신러닝·딥러닝 핵심 공부노트

> 1~14번 수업에서 **반드시 이해해야 하는 것만** 정리한 노트다.  
> 목표: 코드를 외우기보다, 데이터가 모델을 거쳐 예측이 되는 흐름을 설명할 수 있기.

## 0. 전체 흐름 한 장 정리

```text
문제 정의
  → 데이터 확인·EDA
  → X(입력)와 y(정답) 분리
  → train / validation / test 분리
  → 전처리
  → 모델 선택
  → 학습: 예측 → 손실 계산 → 기울기 계산 → 가중치 수정
  → 검증 및 하이퍼파라미터 조정
  → 테스트 데이터로 최종 평가
  → 오분류 분석 및 개선
```

가장 중요한 원칙은 다음 세 가지다.

1. **정답이 숫자면 회귀, 범주면 분류**다.
2. **테스트 데이터는 최종 평가에만 사용**한다.
3. 딥러닝 학습은 항상 `forward → loss → backward → step`이다.

## 1. 머신러닝 기초

### 인공지능, 머신러닝, 딥러닝

- **인공지능(AI)**: 사람처럼 판단하는 기술 전체
- **머신러닝(ML)**: 데이터에서 규칙을 학습하는 AI
- **딥러닝(DL)**: 여러 층의 신경망을 사용하는 머신러닝

관계는 `인공지능 ⊃ 머신러닝 ⊃ 딥러닝`이다.

### 학습 방법

- **지도학습**: 입력 `X`와 정답 `y`로 학습. 회귀와 분류가 대표적이다.
- **비지도학습**: 정답 없이 데이터의 구조나 군집을 찾는다.
- **강화학습**: 행동에 따른 보상을 최대화하도록 학습한다.
- **전이학습**: 큰 데이터로 미리 학습된 모델을 새 문제에 재사용한다.

### 모델과 학습

- **모델**: 입력을 받아 예측을 만드는 함수
- **가중치와 편향**: 학습으로 바뀌는 모델의 값
- **학습**: 예측 오차가 작아지도록 가중치와 편향을 수정하는 과정
- **하이퍼파라미터**: 사람이 정하는 값. 예: 학습률, 배치 크기, epoch 수

## 2. 사이킷런과 지도학습의 기본

사이킷런의 공통 사용법은 매우 단순하다.

```python
model.fit(X_train, y_train)   # 학습
pred = model.predict(X_test)  # 예측
```

### 데이터 분리

```python
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, random_state=2026, stratify=y
)
```

- `random_state`: 같은 결과를 재현하기 위한 난수 고정값
- `stratify=y`: 분류에서 클래스 비율을 유지
- 전처리기를 전체 데이터에 먼저 `fit`하면 **데이터 누수**가 생긴다.

### 분류와 회귀

| 구분 | 예측값 | 예 | 대표 지표 |
|---|---|---|---|
| 분류 | 범주 | 붓꽃 종류, 예약 취소 여부 | Accuracy, Precision, Recall, F1, ROC-AUC |
| 회귀 | 연속된 숫자 | 임대료, 자전거 수요 | MAE, RMSE, R² |

### SVM/SVC

SVC는 클래스 사이의 **경계와 여백(margin)**을 이용하는 분류 모델이다. 핵심은 모든 학습 데이터를 기억하는 것이 아니라 경계 결정에 중요한 **서포트 벡터**를 이용한다는 점이다.

## 3. 전처리와 Pipeline

실제 데이터에서는 모델보다 전처리가 더 중요할 때가 많다.

- 결측치: `SimpleImputer`
- 숫자형 스케일 조정: `StandardScaler`
- 범주형 숫자 변환: `OneHotEncoder(handle_unknown="ignore")`
- 서로 다른 열에 서로 다른 처리: `ColumnTransformer`
- 전처리와 모델 연결: `Pipeline`

```python
model = Pipeline([
    ("preprocessor", preprocessor),
    ("model", estimator),
])
```

Pipeline이 중요한 이유:

- 학습 데이터로만 전처리 기준을 계산해 **데이터 누수 방지**
- 학습과 예측에 **똑같은 전처리 보장**
- 코드 재사용과 교차 검증이 쉬움

`handle_unknown="ignore"`는 테스트 시 처음 보는 범주 때문에 오류가 나는 것을 막는다.

## 4. 회귀 모델과 평가

### 선형 회귀

```text
예측값 = w₁x₁ + w₂x₂ + ... + b
```

실제값과 예측값의 차이인 **잔차**가 작아지도록 가중치를 찾는다.

### 회귀 지표

- **MAE**: 오차 절댓값의 평균. 해석이 쉽고 이상치 영향이 비교적 작다.
- **MSE**: 오차 제곱의 평균. 큰 오차에 큰 벌점을 준다.
- **RMSE**: MSE의 제곱근. 원래 목표값과 단위가 같다.
- **R²**: 모델이 변동을 얼마나 설명하는지 나타낸다. `1`에 가까울수록 좋고, 음수면 평균 예측보다도 나쁠 수 있다.

꼬리가 긴 가격·임대료 데이터에는 `log1p(y)`로 학습하고, 예측 후 `expm1()`로 복원하는 방법을 고려할 수 있다.

### 트리와 앙상블

- **Decision Tree**: 조건을 반복해서 데이터를 나눈다. 이해하기 쉽지만 깊으면 과적합되기 쉽다.
- **Random Forest**: 여러 트리를 독립적으로 학습해 평균/투표한다. 분산과 과적합을 줄인다.
- **Gradient Boosting**: 앞 모델의 실수를 다음 모델이 순서대로 보완한다.
- **GridSearchCV**: 후보 하이퍼파라미터 조합을 교차 검증으로 비교한다.

항상 단순한 `DummyRegressor`와 비교해야 모델이 실제로 의미 있는지 판단할 수 있다.

## 5. 분류 모델과 평가

### 로지스틱 회귀

이름은 회귀지만 **분류 모델**이다. 선형 결괏값을 시그모이드에 통과시켜 0~1 확률로 만든다.

```text
sigmoid(z) = 1 / (1 + e⁻ᶻ)
```

### 혼동행렬

| 실제 / 예측 | Positive | Negative |
|---|---:|---:|
| Positive | TP | FN |
| Negative | FP | TN |

- `Accuracy = (TP + TN) / 전체`
- `Precision = TP / (TP + FP)`: 양성이라고 한 예측 중 정답 비율
- `Recall = TP / (TP + FN)`: 실제 양성을 찾아낸 비율
- `F1`: Precision과 Recall의 조화평균
- `ROC-AUC`: 임계값 전체에 걸친 분류 능력

클래스가 불균형하면 Accuracy 하나만 믿으면 안 된다. 문제의 비용에 따라 임계값을 바꾸고 Precision과 Recall의 균형을 선택한다.

## 6. PyTorch와 텐서

### 텐서

텐서는 다차원 숫자 배열이다.

- 스칼라: 0차원
- 벡터: 1차원
- 행렬: 2차원
- 이미지 배치: 보통 `[N, C, H, W]`

CNN에서 이 순서는 반드시 기억한다.

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = model.to(device)
x, y = x.to(device), y.to(device)
```

모델과 데이터가 서로 다른 장치에 있으면 연산할 수 없다.

### 자동 미분

- `requires_grad=True`: 연산 과정을 기록
- `loss.backward()`: 연쇄법칙으로 각 파라미터의 기울기 계산
- `torch.no_grad()`: 평가할 때 기울기 기록 중단

## 7. 신경망 학습의 핵심 루프

```python
model.train()
for x, y in train_loader:
    x, y = x.to(device), y.to(device)

    optimizer.zero_grad()  # 이전 기울기 제거
    pred = model(x)        # forward
    loss = criterion(pred, y)
    loss.backward()        # 기울기 계산
    optimizer.step()       # 가중치 수정
```

평가할 때는 다음 두 줄이 핵심이다.

```python
model.eval()
with torch.no_grad():
    ...
```

`model.eval()`은 Dropout과 BatchNorm의 동작을 평가 모드로 바꾼다. `torch.no_grad()`는 기울기 계산을 끈다. 역할이 다르므로 둘 다 사용한다.

### Optimizer

- **SGD**: 기울기 방향으로 직접 이동. 단순하지만 학습률에 민감하다.
- **Adam/AdamW**: 파라미터별 학습률을 조절해 대체로 빠르게 학습한다.
- **학습률(lr)**: 너무 크면 발산하고, 너무 작으면 학습이 매우 느리다.

## 8. 선형 회귀와 논리 회귀를 PyTorch로 이해하기

### 선형 회귀

- 출력층: `nn.Linear`
- 손실함수: 보통 `nn.MSELoss()`
- 출력값: 제한 없는 실수

### 이진 분류

- 출력 뉴런: 1개
- 손실함수: `nn.BCEWithLogitsLoss()`
- `BCEWithLogitsLoss` 안에 sigmoid가 포함되므로 학습 전 별도 sigmoid를 붙이지 않는다.
- 예측 시 `torch.sigmoid(logit)` 후 임계값과 비교한다.

### 다중 분류

- 출력 뉴런: 클래스 수
- 손실함수: `nn.CrossEntropyLoss()`
- 모델의 마지막에 Softmax를 붙이지 않는다. CrossEntropyLoss 안에서 처리한다.
- 정답은 클래스 인덱스 형태의 `long` 텐서다.

## 9. 퍼셉트론과 다층 퍼셉트론

퍼셉트론은 `가중합 → 활성화 함수` 구조다. 단층 퍼셉트론은 선형 경계만 만들 수 있어 XOR 같은 문제를 해결하지 못한다.

다층 퍼셉트론(MLP)은 은닉층과 **비선형 활성화 함수**를 사용해 복잡한 비선형 관계를 학습한다.

- Sigmoid: 0~1, 깊은 신경망에서 기울기 소실 가능
- Tanh: -1~1, 역시 기울기 소실 가능
- ReLU: `max(0, x)`, 은닉층의 기본 선택

활성화 함수가 없다면 Linear 층을 여러 개 쌓아도 결국 하나의 Linear 층과 같다.

## 10. Dataset, DataLoader, 데이터 증강

- **Dataset**: 샘플 하나를 어떻게 가져올지 정의
- **DataLoader**: 배치 구성, 셔플, 반복을 담당
- 학습 로더는 보통 `shuffle=True`, 검증/테스트는 `False`

### 데이터 증강

회전, 자르기, 뒤집기 등으로 학습 이미지를 다양하게 만들어 과적합을 줄인다.

중요한 규칙:

- 증강은 **학습 데이터에만** 적용
- 검증/테스트에는 크기 조정, 텐서 변환, 정규화 같은 결정적 전처리만 적용
- 라벨 의미를 바꾸는 증강은 사용하지 않음

`transforms.Compose([...])`는 여러 변환을 순서대로 실행한다.

## 11. CNN

CNN은 이미지의 공간 구조를 유지하면서 작은 필터로 특징을 찾는다.

### 핵심 용어

- **Kernel/Filter**: 이미지에서 특징을 찾는 작은 가중치 행렬
- **Stride**: 필터가 한 번에 이동하는 칸 수
- **Padding**: 가장자리에 값을 추가해 출력 크기를 조절
- **Pooling**: 특징맵 크기를 줄여 계산량과 위치 변화 민감도를 낮춤
- **Channel**: 입력 RGB는 3채널, 합성곱 출력 채널 수는 필터 수

합성곱 출력 크기:

```text
output = floor((input + 2×padding - kernel) / stride) + 1
```

전형적인 CNN 구조:

```text
[Conv → BatchNorm → ReLU → Pool] 반복
  → Flatten 또는 AdaptiveAvgPool
  → Linear
  → 클래스별 logit
```

CNN이 완전연결 DNN보다 이미지에 유리한 이유는 **가중치 공유**와 **지역적 연결**로 파라미터 수를 줄이고 위치 패턴을 학습하기 때문이다.

## 12. 과적합 방지와 좋은 학습 관리

- **BatchNorm**: 중간값의 분포를 안정시켜 학습을 돕는다.
- **Dropout**: 학습 중 일부 뉴런을 꺼 특정 뉴런 의존을 줄인다.
- **Weight decay**: 지나치게 큰 가중치에 벌점을 준다.
- **Scheduler**: 학습 진행에 따라 학습률을 조절한다.
- **Early stopping**: 검증 성능이 더 좋아지지 않으면 학습을 멈춘다.

판단 기준:

- train 성능과 validation 성능이 함께 낮음 → **과소적합**
- train 성능은 계속 좋아지는데 validation 성능 악화 → **과적합**

최고의 모델은 마지막 epoch 모델이 아니라 **검증 성능이 가장 좋았던 모델**이다.

```python
torch.save(model.state_dict(), path)
model.load_state_dict(torch.load(path, weights_only=True))
```

## 13. AlexNet

AlexNet은 깊은 CNN이 대규모 이미지 분류에서 강력하다는 것을 보여준 대표 모델이다. 핵심 아이디어는 여러 합성곱 층, ReLU, Pooling, Dropout을 함께 사용한 것이다.

CIFAR-10 같은 작은 이미지에 적용할 때는 원본 AlexNet을 그대로 외우기보다 다음을 이해한다.

- 입력 이미지 크기에 맞게 구조 조정
- 채널별 평균과 표준편차로 정규화
- train/validation/test 분리
- 검증 손실 기준으로 최적 가중치 저장
- 혼동행렬과 클래스별 성능으로 약한 클래스 확인

## 14. Alien vs Predator: 전이학습

전이학습은 ImageNet 등으로 미리 학습한 모델의 **일반적인 이미지 특징 추출 능력**을 가져와 새 문제에 사용하는 방법이다.

```text
사전학습 AlexNet
  → feature extractor 동결
  → 마지막 분류층을 새 문제에 맞게 교체
  → 새 분류층 학습
  → 필요하면 일부 상위 층을 작은 학습률로 미세조정
```

### Model Freezing

```python
for param in model.features.parameters():
    param.requires_grad = False
```

동결된 파라미터는 업데이트하지 않는다. 데이터가 적을 때 과적합을 줄이고 학습 속도를 높인다.

### 이진 분류의 핵심

- 출력: 이미지당 logit 1개
- 손실: `BCEWithLogitsLoss`
- 확률: `sigmoid(logit)`
- 클래스: 확률을 임계값(보통 0.5)과 비교
- `ImageFolder`의 클래스 번호는 폴더 이름 정렬로 정해지므로 `class_to_idx`를 반드시 확인

단일 이미지도 학습 때와 **동일한 resize·정규화**를 적용하고, 배치 차원을 추가해야 한다.

```python
x = transform(image).unsqueeze(0).to(device)
```

## 절대 헷갈리면 안 되는 것

| 헷갈리는 부분 | 정확한 이해 |
|---|---|
| validation과 test | validation은 모델 선택용, test는 최종 성적표 |
| parameter와 hyperparameter | parameter는 학습됨, hyperparameter는 사람이 정함 |
| logit과 probability | logit은 모델 원출력, 확률은 sigmoid/softmax 적용 결과 |
| `train()`과 `eval()` | Dropout·BatchNorm의 동작 모드를 바꿈 |
| `backward()`와 `step()` | backward는 기울기 계산, step은 가중치 수정 |
| epoch와 batch | epoch는 전체 데이터 1회, batch는 한 번에 처리할 일부 데이터 |
| 회귀와 로지스틱 회귀 | 선형 회귀는 숫자 예측, 로지스틱 회귀는 분류 |
| 증강과 정규화 | 증강은 샘플 다양화, 정규화는 값의 스케일 조정 |

## 실습 전 체크리스트

- [ ] 문제를 회귀/이진 분류/다중 분류 중 하나로 정의했는가?
- [ ] `X`와 `y`의 shape, dtype, 결측치, 클래스 분포를 확인했는가?
- [ ] train/validation/test를 올바르게 분리했는가?
- [ ] 전처리 기준을 train 데이터로만 계산했는가?
- [ ] 모델 출력 크기와 손실함수가 문제 유형에 맞는가?
- [ ] 모델과 텐서를 같은 device로 옮겼는가?
- [ ] 학습에서 `zero_grad → forward → loss → backward → step` 순서를 지켰는가?
- [ ] 평가에서 `eval()`과 `no_grad()`를 사용했는가?
- [ ] validation 기준 최고 모델을 저장했는가?
- [ ] test 결과뿐 아니라 혼동행렬/오분류도 확인했는가?
