# StayHub CSS 구조 분리 디자인

## 목표

1,899줄의 단일 `index.css`를 책임별 파일로 분리하고, 기존 스타일과 모던 부티크 오버라이드의 중복을 통합한다. 화면 모양, 반응형 동작, JSX 클래스 이름은 변경하지 않는다.

## 파일 구조

`src/index.css`는 다음 파일을 순서대로 불러오는 진입점만 담당한다.

1. `styles/tokens.css`: 색상, 그림자, 반경 등 디자인 토큰
2. `styles/base.css`: 박스 모델, body, 링크, 폼 요소 기본값, 접근성 포커스
3. `styles/layout.css`: 헤더, 내비게이션, main, page, 공통 제목 레이아웃
4. `styles/components.css`: 버튼, 입력 필드, 상태 박스, 배지, 공통 상태 표현
5. `styles/hotel.css`: 히어로, 검색, 호텔 목록·카드·상세·관리·호텔 폼
6. `styles/room.css`: 객실 목록·카드·이미지·예약 요약·객실 소유자 동작
7. `styles/reservation.css`: 예약 검색·목록·상세·완료 화면
8. `styles/auth.css`: 로그인·회원가입 폼
9. `styles/responsive.css`: 900px 및 700px 반응형 규칙, reduced-motion

## 통합 원칙

- 동일 선택자가 여러 번 선언된 경우 현재 파일의 cascade 결과를 보존한 하나의 규칙으로 합친다.
- 공통 입력 스타일은 `components.css`에 한 번만 선언하고 페이지 파일에서는 배치만 담당한다.
- CSS 변수는 하드코딩된 모던 부티크 색상을 대체할 수 있는 범위에서 사용한다.
- 특이성 증가를 피하고 기존 JSX 클래스 이름을 그대로 유지한다.
- `!important`는 기존 `.hero-label`의 불필요한 사용을 제거하고 정상 cascade로 해결한다.
- 모바일 규칙은 기본 규칙과 같은 파일에 흩어 놓지 않고 `responsive.css`에 모은다.

## 호환성

- Vite의 CSS `@import` 처리 방식을 사용하며 새 패키지를 추가하지 않는다.
- 기존 호텔·객실 이미지 레이아웃과 플레이스홀더를 유지한다.
- 최소 화면 폭 320px, 900px 태블릿, 700px 모바일 기준을 유지한다.
- 키보드 포커스와 `prefers-reduced-motion` 접근성 규칙을 유지한다.

## 검증 기준

- `index.css`에는 9개의 `@import` 외에 스타일 규칙이 없어야 한다.
- 모든 기존 JSX `className`이 분리된 CSS 파일 중 하나에 대응해야 한다.
- 각 CSS 파일과 전체 결합 결과의 중괄호가 균형을 이뤄야 한다.
- Vite 프로덕션 빌드가 성공해야 한다.
- 리팩터링 전후 핵심 선택자와 반응형 선택자가 모두 존재해야 한다.
- 새 CSS 구조에서 동일 선택자의 불필요한 중복 선언이 없어야 한다.

## 범위 제외

- JSX와 JavaScript는 수정하지 않는다.
- 색상, 크기, 여백 등 승인된 디자인을 새로 변경하지 않는다.
- 기존 ESLint의 React effect 오류는 이번 작업에서 수정하지 않는다.
